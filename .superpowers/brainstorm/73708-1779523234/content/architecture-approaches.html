Architecture Approaches

Three ways to structure the Multi-Mailbox Management System

Decided So Far

React + TypeScript • Python + FastAPI • PostgreSQL • Docker Compose • Chinese UI • No auth • Microsoft Graph API

A

Ant Design Pro — 运维风格 (Recommended)

Use Ant Design component library for the entire UI. It provides production-ready data grids (Table), modals, forms, pagination, tags, and status indicators out of the box — matching almost every PRD requirement directly.

Pros

  • ProTable handles sorting, filtering, pagination, row selection natively
  • Chinese locale support built-in
  • Fastest time-to-feature — most PRD components map 1:1 to Ant Design
  • Mature and battle-tested for admin/ops tools

Cons

  • Looks like a standard admin panel — less visually distinctive
  • Large bundle size (~1MB+ for full Ant Design)
  • Opinionated styling, harder to customize deeply

Backend: FastAPI monolith + Celery/ARQ worker for background token health checks. Single-process API, separate worker container.

B

Custom Design — 精品定制风格

Build with TanStack Table + Radix UI + Tailwind CSS. Full control over every visual detail. Create a distinctive, polished operations tool that feels premium — not generic admin.

Pros

  • Completely custom look — memorable and distinctive
  • Smaller bundle, only import what you need
  • Full control over data grid behavior and styling
  • Modern, headless component approach

Cons

  • 2-3x more frontend development time
  • Must build pagination, row selection, batch operations from scratch
  • No built-in Chinese locale — manual i18n needed

Backend: Same FastAPI monolith + background worker. No difference on the backend side.

C

Hybrid — Ant Design + 定制增强

Use Ant Design as the foundation but apply a custom design theme with distinctive typography, colors, and micro-interactions. Get the speed of a component library with a unique visual identity.

Pros

  • Fast development — Ant Design handles complex components
  • Visually distinctive through custom theming (ConfigProvider)
  • Chinese locale + custom aesthetic = best of both worlds
  • Can selectively replace individual components with custom ones

Cons

  • Theme overrides can fight Ant Design defaults
  • Some customization limits compared to fully headless approach
  • Still carries Ant Design's bundle size

Backend: Same FastAPI monolith + background worker. No difference on the backend side.

Backend Architecture (same for all options)

FastAPI monolith — single API service handling all REST endpoints
ARQ (async Redis queue) — background worker for token health checks, decoupled from the API
PostgreSQL — encrypted credential storage (AES-256 via Python cryptography lib)
Docker Compose — 4 containers: frontend (Nginx), API, worker, PostgreSQL (+ Redis for task queue)
