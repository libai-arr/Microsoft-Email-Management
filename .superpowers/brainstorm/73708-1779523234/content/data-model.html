Section 2: Data Model

PostgreSQL 数据库表结构设计

🔑 Primary Key 🔗 Foreign Key 🔒 AES-256 加密字段 ◆ 索引

mailboxes

核心表
🔑id UUID 主键，gen_random_uuid()
◆email VARCHAR(255) 邮箱地址，唯一索引，支持模糊搜索
🔒password_encrypted BYTEA AES-256-GCM 密文存储
🔒client_id_encrypted BYTEA Azure AD 应用 Client ID 密文
🔒refresh_token_encrypted BYTEA OAuth2.0 Refresh Token 密文
🔗group_id UUID 所属分组 FK → groups.id，可为 NULL（默认分组）
◆token_status VARCHAR(20) 令牌状态：normal / checking / expired
channel VARCHAR(20) 授权通道标识，默认 "O2" (OAuth2.0)
token_checked_at TIMESTAMPTZ 最后一次令牌健康检查时间
created_at TIMESTAMPTZ 导入时间，DEFAULT now()
updated_at TIMESTAMPTZ 最后更新时间

groups

辅助表
🔑id UUID 主键
◆name VARCHAR(100) 分组名称，唯一
description TEXT 分组描述，可选
created_at TIMESTAMPTZ 创建时间

audit_logs

审计表
🔑id BIGSERIAL 自增主键
◆action VARCHAR(50) 操作类型：batch_copy / batch_export / batch_delete / import_overwrite
target_count INTEGER 操作涉及的记录数
detail JSONB 操作详情（受影响的邮箱 ID 列表等）
ip_address INET 操作来源 IP
created_at TIMESTAMPTZ 操作时间

Table Relations

mailboxes N : 1 groups — 每个邮箱属于一个分组（可为空 = 默认分组）
audit_logs ∞ mailboxes — 审计日志通过 JSONB detail 字段松耦合关联，不用 FK

Design Decisions

  • • 邮件数据不存储在数据库中 — 每次通过 Graph API 实时拉取，避免存储海量邮件正文
  • • Access Token 缓存在 Redis 中（TTL ~50min），避免重复刷新请求
  • • 加密密钥通过 环境变量 注入（ENCRYPTION_KEY），不存储在数据库或代码中
  • • audit_logs 与 mailboxes 松耦合 — 即使邮箱被删除，审计记录保留
  • • email 字段唯一索引 — 导入时去重，防止重复录入同一邮箱
