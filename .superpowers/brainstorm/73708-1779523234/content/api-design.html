Section 3: API Design

RESTful API 端点设计 — FastAPI 路由结构

邮箱管理

/api/mailboxes
GET
/api/mailboxes
分页查询邮箱列表，支持搜索和分组筛选
Query: ?page=1 &page_size=10 &search=keyword &group_id=uuid
POST
/api/mailboxes/import
批量导入邮箱（追加模式）。接收前端已解析的结构化数组
Body: { items: [{ email, password, client_id, refresh_token }], mode: "append" | "overwrite" }
POST
/api/mailboxes/export
导出选中或全部邮箱数据为 CSV/Excel 文件流
Body: { ids?: uuid[], format: "csv" | "xlsx", include_all?: bool }
DELETE
/api/mailboxes/batch
批量删除选中的邮箱
Body: { ids: uuid[] }
PATCH
/api/mailboxes/batch/group
批量设置分组
Body: { ids: uuid[], group_id: uuid }
POST
/api/mailboxes/batch/copy
批量获取复制数据（账号/密码/账号----密码）
Body: { ids: uuid[], type: "email" | "password" | "combined" } → 返回拼接文本
DELETE
/api/mailboxes/{id}
删除单个邮箱

分组管理

/api/groups
GET
/api/groups
获取所有分组列表（含每组邮箱计数）
POST
/api/groups
创建新分组
Body: { name: string, description?: string }
PUT
/api/groups/{id}
更新分组名称/描述
DELETE
/api/groups/{id}
删除分组（邮箱回归默认分组）

邮件查看

/api/mailboxes/{id}/emails
GET
/api/mailboxes/{id}/emails
获取邮件列表（懒加载分页），支持收件箱/垃圾箱切换
Query: ?folder=inbox|junk &page=1 &page_size=20 &search=keyword
GET
/api/mailboxes/{id}/emails/{message_id}
获取单封邮件的完整 HTML 正文（安全过滤后）

令牌状态

/api/tokens
GET
/api/tokens/status
批量获取令牌健康状态（前端轮询接口）
Query: ?ids=uuid1,uuid2,... → [{ id, status, checked_at }]
POST
/api/tokens/check
手动触发选中邮箱的令牌健康检查（异步入队）
Body: { ids: uuid[] } → Worker 异步执行

API Design Decisions

  • 批量复制（batch/copy）返回拼接文本而非原始数据 — 密码解密在后端完成，前端仅负责写入剪贴板
  • 导出（export）使用 POST 而非 GET — 因为需要传递可能很长的 ID 列表
  • 邮件接口不做缓存 — 每次实时调用 Graph API，确保最新数据
  • 令牌状态轮询间隔建议 30 秒，避免对后端造成压力
  • 所有敏感操作（批量复制/导出/删除/覆盖导入）自动记录 audit_logs
  • 邮件正文返回前执行 HTML sanitize（移除 script/iframe/事件处理器），防止 XSS
